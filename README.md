# Tween

**Between every frame.** Tween is a desktop app that makes video smoother by creating the frames your footage never had. It turns 24 or 30 fps into 48, 60, 120 fps or any rate up to 240. It runs on your own graphics card, and your videos never leave your device.

> **Status:** pre-release (v0.1.0). Installers for Windows, macOS and Linux are built automatically on every change. They are not code-signed yet, so Windows and macOS show a warning on first launch.

---

## Why Tween

- **Smooth motion from any footage.** Tween uses RIFE, an AI frame-interpolation model, to create new in-between frames instead of duplicating or blending old ones.
- **Private by design.** Everything runs locally on your GPU. No uploads, no account, no internet needed after setup.
- **Works on the GPU you have.** NVIDIA, AMD and Intel graphics through Vulkan, including integrated graphics, with automatic CPU fallback.
- **Simple first run.** Onboarding checks your system, downloads the engine and FFmpeg (about 72 MB for the engine), tests each GPU, and picks the fastest one for you.
- **Clean cuts.** Scene-cut detection stops Tween from blending two different shots together.
- **Fast hardware encoding.** NVENC, AMD AMF, Intel Quick Sync or Apple VideoToolbox when available, with x265 or x264 as a fallback.
- **Made for editors.** A real preview player, timeline thumbnails, trim in/out (`I` / `O`), Space to play, side-by-side Original vs Interpolated, and Show in folder.

## Frame-rate options

Tween offers targets that make sense for your source:

| Source | Options shown |
|---|---|
| 24 fps | 2× 48, 3× 72, 4× 96, 60, 120, Custom |
| 30 fps | 2× 60, 3× 90, 4× 120, 144, 240, Custom |
| 60 fps | 2× 120, 3× 180, 4× 240, 144, Custom |

Custom accepts any whole rate above the source, up to 240 fps. Fractional sources (23.976, 29.97, 59.94) are handled exactly.

## Models

| Name in app | Model | Best for |
|---|---|---|
| **Smooth** (default) | RIFE v4.26 | Newest model. The best choice for most videos |
| **Detail** | RIFE v4.25 heavy | Cleaner edges in fast motion |
| **Fast** | RIFE v4.22 lite | Older or integrated GPUs |

## Benchmarks

All numbers below are **measured**, not estimated. Each row says which version and which machine produced it. New results are added as the engine gets faster.

### How we measure

- **Clip:** 8 seconds of generated 1080p (1920×1080) video at 24 fps. The first half is FFmpeg's `testsrc2` moving test pattern and the second half is a `mandelbrot` zoom, with a hard scene cut at 4 s and a 440 Hz audio track. It is generated by the benchmark itself, so anyone can reproduce it.
- **Jobs:** Smooth at 2× (24 → 48 fps), Smooth to 60 fps, Fast at 2×, Detail at 2×. Each job includes scene analysis, interpolation, encoding with audio, and cleanup.
- **Metric:** **output fps** = frames written ÷ total wall-clock time for the whole job. Higher is better. "Time for 10 minutes" projects that rate to a 10-minute 24 fps 1080p video at 2× (28,800 output frames).
- **Conditions:** laptop on mains power, no other heavy work running.
- **Run it yourself:** `npm run test:gpu` from the repo root. Results and output videos go to `out/smoke/`. A Rust-pipeline benchmark, `npm run bench` in `app/`, is being added.

### Results

**Test machine A:** Windows 11 laptop, NVIDIA GeForce RTX 4050 Laptop GPU (6 GB), Intel UHD Graphics 770, 12 CPU threads, 16 GB RAM, NVENC HEVC encoder.

| Version | Engine mode | Job | Output fps | Time for 10 min @ 2× |
|---|---|---|---|---|
| 0.1.0 reference pipeline | File (PNG on disk) | Smooth, 2× | **17.8** | ~27 min |
| 0.1.0 reference pipeline | File (PNG on disk) | Smooth, to 60 fps | **14.7** | — |
| 0.1.0 reference pipeline | File (PNG on disk) | Fast, 2× | **18.0** | ~27 min |
| 0.1.0 reference pipeline | File (PNG on disk) | Detail, 2× | **14.6** | ~33 min |
| Speed update 1 (quick wins) | File, tuned | Smooth, 2× | *pending* | *pending* |
| Speed update 2 (streaming engine) | Stream (no disk) | Smooth, 2× | *pending* | *pending* |

**GPU self-test on the same machine** (onboarding runs a short interpolation on each GPU and picks the fastest): RTX 4050 Laptop **1.6 s**, Intel UHD 770 **4.9 s**. Tween chose the RTX.

**What these numbers tell us:** Fast (the smallest model) was no quicker than Smooth. The GPU is not the limit today. Most of the time goes into writing and reading frame images on disk, and reloading the model for each chunk. That is exactly what the two speed updates target:

1. **Quick wins:** lighter PNG compression, tuned engine threads, bigger chunks (fewer model reloads), overlapping stages, and hardware decoding.
2. **Streaming engine:** a streaming mode for the MIT-licensed RIFE engine. The model loads once and frames flow from FFmpeg through the GPU and back in memory, with no image files on disk. File mode stays as the automatic fallback, and streaming only becomes the default once it is proven faster with identical output.

### Quality checks

- Scene cuts produce no ghosting: the frames on each side of the 4 s cut were checked by eye.
- Frame counts are exact: 2× of 192 frames gives 384, and 60 fps from 8 s gives 480.
- Audio is kept and stays in sync with the trimmed range.
- Automated tests cover chunk joins, fractional rates, trim, scene cuts and cancel. They use a stand-in engine so they run on any machine, including CI.

### Submit your result

Run `npm run test:gpu` and open an issue with the printed `setup` block and the four `ok` lines. Results from AMD, Intel Arc, Apple Silicon and Linux machines are especially welcome.

## Supported systems

| | Windows 10/11 | macOS 12+ (Apple Silicon and Intel) | Linux (x64, glibc) |
|---|---|---|---|
| Installer | NSIS `.exe` (per-user, no admin) | `.dmg` | AppImage, `.deb` |
| GPU | NVIDIA, AMD, Intel (Vulkan) | Apple GPU (MoltenVK) | NVIDIA, AMD, Intel (Vulkan) |
| Hardware encode | NVENC, AMF, Quick Sync | VideoToolbox | NVENC, VAAPI-class via FFmpeg |
| Status | Tested on a real GPU | Builds in CI; GPU run pending | Builds in CI; GPU run pending |

There is no GPU requirement. Without a working Vulkan device, Tween runs on the CPU (much slower) and tells you so.

## How it works

1. **Analyse:** FFmpeg reads the video and finds scene cuts.
2. **Interpolate:** RIFE creates the in-between frames on your GPU, in chunks, so long videos never need much disk space at once. Frames are placed on an exact timeline, so the output length matches the input to the frame.
3. **Encode:** frames are encoded with the best hardware encoder available, and the original audio is copied in.
4. **Done:** compare Original vs Interpolated side by side, then open the file in its folder.

## Build from source

The app is built with **Tauri 2, Rust and React**, in `app/`. The older Electron reference pipeline in `src/` is kept for the benchmark and the reference tests.

### Prerequisites

- [Node.js](https://nodejs.org) 20+
- [Rust](https://www.rust-lang.org) (stable)
- Platform dependencies:
  - **Windows:** Microsoft C++ Build Tools and WebView2 (pre-installed on Windows 10/11)
  - **macOS:** Xcode Command Line Tools (`xcode-select --install`)
  - **Linux (Ubuntu/Debian):**
    ```bash
    sudo apt-get update && sudo apt-get install -y \
      libwebkit2gtk-4.1-dev build-essential curl wget file \
      libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev squashfs-tools
    ```

### Develop

```bash
cd app
npm ci
npm run tauri dev
```

The engine and FFmpeg are downloaded by onboarding on first launch. You do not need to install them yourself.

### Test

```bash
# Rust unit and end-to-end tests (stand-in engine; needs ffmpeg and node on PATH)
cargo test --manifest-path app/src-tauri/Cargo.toml

# Reference pipeline tests
npm test

# Real GPU benchmark (downloads the engine on first run)
npm run test:gpu
```

### Package

```bash
cd app
npm run tauri build
```

Output goes to `app/src-tauri/target/release/bundle/`. The installers do not bundle RIFE or FFmpeg, which keeps the Windows installer at about 2 MB.
